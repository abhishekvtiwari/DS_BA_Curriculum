## Per-chapter verdicts

- **Ch 10 — Spreadsheet Fundamentals: Excel & Google Sheets** (33: 4H/16M/13L) — A strong, practical chapter. Riverstone's 330-line export is used consistently, almost every formula result is shown, the numbers reconcile to the rupee, and the "check what a cell contains" habit is taught well. The main problems for a first-time reader: (1) setup is three lines inside §10.1, with no first-run check (approved §10.0 is missing), and the "Back to Chapter 4" exercises aren't here yet; (2) formulas and functions are used in §10.3–§10.5 before §10.6/§10.7 teach `=` and functions, and one of those early formulas points at the wrong column; (3) a wrong count (135 vs 125 "wrong real dates") repeats in four places; (4) the chapter cites "Chapter 13" as the source of numbers the reader already met in Chapter 4, and it has four SQL/pandas preview boxes (M.10).
- **Ch 11 — The Spreadsheet, Mastered: Excel & Google Sheets** (34: 8H/17M/9L) — Excellent professional content. The numbers reconcile across every method (SUMIFS, pivot, FILTER, Power Query, DAX, QUERY all give ₹4,335,471), and the month-end-pack story is one of the best in the book. For a reader who finished Chapter 10 two weeks ago, though, it's two or three chapters in one: ~150 functions and features, M code, DAX, and a competition case. Several code blocks do four or five new things at once, and some are unrunnable as written: the "spare sheet" examples in §11.3, the cross-workbook merge in §11.7, and the table names in the §11.8 model. It also carries five SQL preview boxes, an SQL column in Figure 11.3, and a warm-up exercise that can only be answered with SQL (M.10).
- **Ch 12 — Databases & SQL Foundations** (50: 2H/26M/22L) — One of the strongest chapters in the book. The data is small enough to check by eye, and every one of the ~110 printed results I rechecked matches the data. The traps (AND/OR, NULL, fan-out, ON vs WHERE, MySQL dates and collation) are taught with real, reproducible outputs. For a first-time SQL reader it has four real problems. (1) It never says how to run a query in DBeaver, and it shows psql-style output that the reader's DBeaver grid won't look like. (2) Keywords appear before their sections: ORDER BY in six queries before §12.7, JOIN in §12.9, subqueries in §12.10, date arithmetic before "Working with dates", and the MySQL monthly report before the PostgreSQL original. (3) A few early queries each bring in 3–5 new ideas at once. (4) §12.13 (DDL in two dialects) is a chapter-sized load inside an already long chapter. The four approved moves into the chapter (install without Ch 6, the March issue-tree queries, the ch07 MySQL file, the ROUND note) are specified below with verified SQL and outputs.
- **Ch 13 — SQL for Real Analysis** (27: 0H/10M/17L) — One of the strongest teaching chapters so far. Every query is shown with its real output, most have a "How it works" breakdown, and every number I recomputed matches (to within rounding). The problems are about order and completeness, not quality. The recursive CTE in the MySQL section comes before it is taught (M.7). Running totals depend on the default window frame, which is explained two subsections later. One narrative claim contradicts its own table ("under 80% … through July"). Temporary tables and a working CREATE VIEW (output, how to check it, how to replace it) are promised but never shown. §13.7 packs ten patterns into one sitting.
- **Ch 14 — Data Cleaning & Preparation** (36: 5H/11M/20L) — A good method: load as text, profile, fix, validate, reconcile, document. It uses a very well built dataset: every number I recomputed ties out, from the 25,976 raw rows down to ₹311,797.50 explained. The branch league-table story is one of the best in Part II. For a first-time reader, though, the SQL half is shown as results, not as teaching. Regular expressions are used from §14.2 onward and never taught. The actual cleaning pipeline (the `typed` step, y/m/dd date parts, `clean_order_lines`, `clean_customers`, `dq_order_issues`) exists only in a companion script and is used before it is built. Several key blocks are fragments that cannot be run. Loading starts with terminal commands (M.4). pandas appears across the chapter, not only in §14.13 (M.2).
- **Ch 15 — Data Visualization Principles** (25: 1H/10M/14L) — One of the strongest chapters in Part II. The principles are accurate, well sourced (Cleveland–McGill, Anscombe, Tufte, WCAG), and anchored on Riverstone numbers that almost all recompute correctly. The real-world story is excellent. For a first-time reader the problems are structural. §15.14 teaches pandas and matplotlib before Python exists (M.2), and Python also turns up in the Tools line, the project, and three exercises. The prerequisite claim that Ch 4 taught "spread" is false. One factual slip in the story: the note says the Q4 plan assumed 33% growth, but that figure applies to October only.
- **Ch 16 — Business Intelligence with Power BI** (36: 7H/17M/12L) — This is professional, current content: accurate 2026 licensing, the right modelling doctrine, SQL cross-checks for every card, and a strong real-world story. For a first-time reader it has four blocking problems. (1) There is no install section. (2) The fact table is never actually built: the chapter wavers between importing raw `orders` + `order_items` and using the `sales_lines` view, then writes measures against columns that don't exist in either version. (3) Several DAX blocks are wrong or would print the wrong thing: the crore format string, the "Last Refreshed" measure, the RLS "no role sees all" claim, and the Answer 22 measure. ## Cross-cutting themes (one decision can cover many rows)

1. Code shown before it is taught — apply the sequence rule book-wide.
2. Tools/libraries never installed (scikit-learn, scipy, PyTorch, NLTK, Dagster web, Spark/Java, Kafka, Docker/Terraform, FastAPI/MLflow, LLM SDK, psql) — extend just-in-time setup to every tool.
3. Big code blocks introducing 5–15 ideas at once — one idea per cell, output shown, every line and argument explained.
4. No by-hand example before methods (stats formulas, most ML algorithms, metrics, backprop) — plain idea → tiny by-hand → spreadsheet → code.
5. Foundations never taught: logarithms, chain rule, Python classes, JS/TS/HTML, YAML/Jinja, regex, autocorrelation, topological sort, isolation levels — add primers where first needed.
6. Hidden companion code / black-box outputs (Ch 14, 27, 46, 51, 55, 57, 58).
7. Printed outputs that are errors or can't come from the code (Ch 17, 18, 42, 46, 51, 54, 78) — re-run every chapter before print.
8. Wrong cross-references throughout ("Chapter 19" regression, "Chapter 38" evaluation, "Chapter 52" MLOps, "Chapter 23" semantic layer, non-existent "Chapter 76") — one generated-index pass after moves.
9. Part VIII: placeholder/self-referential "Learn it in" pointers, 72A/76A/76B numbering, questions on untaught topics, no difficulty labels, "Passes" tier misdefined.
10. Riverstone facts disagree (warehouse DuckDB vs Postgres; hourly rate ₹300 vs ₹1,200; exchange rate; Meera and Farah timelines; sensor dataset Ch 40 vs 48; lead vs churn AUC mix-ups; invoicing manual vs automatic) — create one Riverstone fact sheet.
11. Drafting/authoring leftovers ("Appendix G" ×59, "first edition", "this chat doesn't have…", "blueprint", coordinator notes, AI-authoring note in Ch 67, build scripts named as reader files).
12. Time needed estimates too low in many chapters (Ch 11, 12, 28, 35, 36, 39, 40, 52).
13. Claims needing outside verification (PayScale Ch 8, LLM prices Ch 54, AWS prices Ch 65, DPDP/GDPR/EU AI Act Ch 64, MySQL versions).
14. Integrity of examples/advice (Ch 54 mock numbers called real; Ch 81 first-person use of others' stories; textbook projects presented as candidate's own work).
