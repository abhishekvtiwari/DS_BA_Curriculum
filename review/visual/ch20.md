# Visual review — Ch20-Automating-Reports-and-Delivering-Insights.pdf (29 pages)
Verdict: A well-structured chapter. Its three diagram figures (20.1, 20.2, 20.4) are drawn wide and set at 4.4–5.5 pt, which is unreadable in print. The one raster image, the Daily Sales Flash screenshot (Fig 20.3), is sharp on screen but only 187 ppi at print size. A cron command wraps inside "--send", so a reader could copy it wrong. Otherwise the chapter shares the batch's cover, contents, exercise-number and code-wrap patterns.

Page numbers below are **PDF pages**; the printed folio is PDF page − 1 ("n / 28").

Automated checks:
- **Fonts:** all embedded (Lora, Poppins, DejaVu Sans/Mono/Serif). "₹" and arrows fall back to DejaVu Serif (pp. 6, 12, 14, 20, 22–23, 26–29). The ₹ inside the Fig 20.3 screenshot is part of the bitmap and is fine. No tofu.
- **Raster image** (pdfimages): one image, p. 10, Figure 20.3. It is 1280 × 1238 px RGB (ICC) at **187 × 187 ppi** effective, placed at about 493 × 477 pt (full text width) with a matching aspect ratio, so it is not stretched. The image text is crisp at 1:1 (anti-aliased browser render). At 187 ppi the 9–10 px-high tick labels and footer line will print soft. 300 ppi needs about a 2050 px wide capture.
- **Figure text size:** Fig 20.1 4.7–5.5 pt; Fig 20.2 4.5–5.4 pt; Fig 20.4 4.4–5.5 pt. Fig 20.3 (raster) tick labels and footer are ≈ 6.5–7 pt equivalent, which is acceptable.
- **Text outside margins:** list numbers "10." (p. 22, project steps) and "10."–"27." (p. 25) at x = 48 pt, first digit clipped.
- **Blank-area scan:** p. 9 55% empty, p. 8 28%. p. 29 is the chapter end.
- **Code-wrap scan:** column-0 continuations on pp. 16, 17 (×2). The p. 8 wrap is a real `\` continuation, which is fine.
- Every page was viewed, and all four figures, every table and the code blocks were zoomed at 200–250 dpi. The raster image was extracted and inspected at native resolution.

## Patterns (things that repeat on many pages — describe once, list pages)
- **Diagram figures at 4–5.5 pt** (pp. 4, 5, 16), the same root cause as Ch17 and Ch25–27. The matplotlib-style chart inside the raster screenshot is fine.
- **Tables** (pp. 5, 6, 7, 13, 15, 19–20) are consistent: navy header, zebra rows, left-aligned text. There are no numeric columns apart from the screenshot's, which are right-aligned.
- **Callouts:** Watch out (p. 6) and a blue "Note on what was run" (p. 21). They are consistent.
- **Colour:** Fig 20.2 uses green "automatic" against red "MANUAL", but every chip is also labelled in text, so it survives colour-blindness and greyscale.
- **Folios** "n / 28". The running footer is correct.
