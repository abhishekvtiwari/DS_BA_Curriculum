# Visual review — Ch26-The-Professional-Toolkit.pdf (33 pages)

Verdict: Code blocks, tables and body text are tidy, and terminal output is readable. The main problems are float placement and figure scale. Three pages are 20–34% empty because a figure moved to the next page (pp. 4, 11, 16). Figures 26.1 and 26.3 are set at 4.3–6.9 pt, while Figure 26.2 is readable, so figure sizing is inconsistent even within the chapter. Narrow first columns split command flags mid-token ("--no-/verify", "--/oneline", "python-/version:").

Page numbers below are **PDF pages**; the printed folio is PDF page − 1. The half-empty "page 10" that was already noticed is printed folio 10, which is PDF p. 11.

## Patterns (things that repeat on many pages — describe once, list pages)
- **Figure floats leave holes** on pp. 4, 11 and 16, each with a lead-in stranded above the gap. The renderer does not back-fill text after moving a figure. Fix globally by allowing text to flow past floats, or by adding "keep lead-in with figure".
- **Inconsistent figure scaling:** Fig 26.2 is at 7 pt or more, while 26.1 and 26.3 are 4–6 pt. Define one scale rule: draw every figure at column width.
- **Code blocks:** DejaVu Sans Mono 7.9 pt on pale grey. It is readable but small next to 10.4 pt body, so consider 8.5 pt. Terminal blocks mix commands and output in one style (pp. 6, 8, 9, 13–16). The "$" prompt is the only cue, and there is no weight or colour difference for output. Python, terminal and output blocks get a grey left rule; SQL blocks in Ch27 get a dark-blue rule.
- **Inline code in bold bullets** ("`git init` creates…") uses bold mono 8.6 pt, which sits heavier than the Lora line. It is consistent throughout, so this is a style choice.
- **Tables:** first-column bold varies (p. 5, "The working directory" bold; pp. 20–21 regular).
- **Folios** "n / 32", chapter-local (see Ch25).
