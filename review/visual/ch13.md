# Visual review — Ch13-SQL-for-Real-Analysis.pdf (51 pages)
Verdict: A long, code-heavy chapter. Code and psql output are set cleanly, the callouts are consistent, and the tables are tidy. The main problems are layout, repeated throughout: about 15 queries wrap long lines back to column 0 with no continuation marker, and page breaks strand lead-ins, run-in headings and answer numbers with 20–40% blank space below. All four figures are below the 7 pt print minimum (5.2–6.9 pt), though less badly than in Ch27. Two-digit exercise numbers are **clipped**: the leading "1" is cut in half, which is worse than the "hanging" that the pilot recorded. The cover still says "Draft chapter", while Ch14–16 say "Approved".

Page numbers below are **PDF pages**. The printed folio is PDF page − 1 ("n / 50").

Automated checks:
- **Fonts:** all embedded (Poppins headings, Lora 10.4 pt body, DejaVu Sans tables, DejaVu Sans Mono code). "₹" falls back to DejaVu Serif (pp. 10, 15, 17–19, 25, 47, 51), and so does "→" (pp. 25, 31). The difference is barely visible. No tofu.
- **Images:** none raster. All figures are vector.
- **Figure text size (pdfplumber char sizes):** Fig 13.1 5.4–6.9 pt; Fig 13.2 5.6–6.1 pt; Fig 13.3 5.2–6.3 pt; Fig 13.4 5.2–6.6 pt.
- **Text outside margins:** the exercise numbers "10."–"16." at x = 48 pt (pp. 41–42). They are clipped (see V13.1).
- **Blank-area scan (text ends above ~80%):** p. 9 (74%), p. 22 (67%), p. 26 (70%), p. 34 (63%), p. 45 (60%), p. 48 (58%), p. 49 (68%). p. 2 is the contents page.
- Every page was viewed on 3×2 contact sheets. All four figures, the tables and the wrapped code blocks were zoomed at 150–300 dpi.

## Patterns (things that repeat on many pages — describe once, list pages)
- **Code wrapping to column 0**, about 15 blocks (V13.6). This is the biggest reading problem in the chapter, since readers copy these queries.
- **Page-foot strandings and blank areas** (pp. 9, 22, 26, 28, 32, 34, 42, 45, 48, 49, 50): lead-ins ending in ":", run-in heads ("How it works.") and answer numbers. One global rule (keep-with-next for "…:" paragraphs, run-in heads and answer numbers, and allow code/output blocks longer than ~15 lines to split) fixes most of them.
- **Figures slightly too small** (5.2–6.9 pt, all four figures). This is less extreme than Ch25–27 but has the same root cause.
- **Code styling:** SQL input has a dark-blue left rule and psql output a grey rule, a clear distinction. MySQL output (pp. 33–35, 50) uses the "+---+" boxed style, which correctly signals the other tool.
- **Callouts** (Tool note, Real-life habit/example, Spreadsheet link, Dialect note, Watch out, Interview extra point) are styled consistently. Watch out uses peach with an orange rule, the others blue.
- **Tables** repeat the dark-blue header and have no split rows. Numbers in psql output are right-aligned by the tool.
- **Folios** "n / 50" are chapter-local. The running footer "Analyst to Architect · Chapter 13 · SQL for Real Analysis" is correct throughout.
