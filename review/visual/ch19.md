# Visual review — Ch19-Spreadsheet-Automation.pdf (27 pages)
Verdict: The whole chapter is printed at about 77% scale. Body text is about 8 pt instead of 10.4 pt, code about 6.1 pt, and table text about 6.3 pt, while the running footer stays at normal size. It is the only chapter in this batch set this way, and it makes the dense VBA listings hard to read in print. Apart from that, layout is tidy. It has no figures, one half-empty page, a stranded run-in heading, clipped exercise numbers, and the usual cover/contents labels. The chapter title also differs between the cover/footer and the heading/contents.

Page numbers below are **PDF pages**; the printed folio is PDF page − 1 ("n / 26").

Automated checks:
- **Fonts:** all embedded (same families as Ch17/18, plus DejaVu Serif Italic). "₹" and arrows fall back to DejaVu Serif (pp. 4–6, 8, 10, 13, 15–16, 20–22, 26–27). No tofu.
- **Text size (word-box histogram, all pages):** Lora body box height 11.0 pt vs 14.3 pt in Ch17/18/20–22, i.e. **8.0 pt body**. Code 7.1 pt boxes ≈ **6.1 pt** (Ch17: 7.9 pt). Tables ≈ **6.3 pt**. Inline code in text ≈ 5.4–5.6 pt. The footer is unchanged (8.7 pt boxes), so the content area was scaled, not the page.
- **Images:** none, and no figures.
- **Text outside margins:** exercise numbers "10."–"28." at x = 48 pt, first digit clipped (pp. 24–25).
- **Blank-area scan:** p. 9 54% empty. p. 27 is the chapter end.
- **Code blocks do not wrap** in this chapter (unlike Ch17/18). Long VBA and HTML-string lines (e.g. `bodyHtml` p. 12, `onFormSubmit` HTML p. 18) run the full width. This is the likely trigger for the shrink-to-fit.
- Every page was viewed on 6-up sheets, and the code, tables and body were zoomed at 200 dpi.
