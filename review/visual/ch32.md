# Visual review — Ch32-Analytics-Engineering-with-dbt.pdf (35 pages)

Verdict: A code-heavy chapter that holds together well. The YAML, SQL, terminal and output blocks are consistent and seldom wrap badly. The lineage diagram (Fig 32.1) is the main visual problem: its edges run straight through the "dim_product" and "dim_sales_rep" labels, have no arrowheads, and are 5.3 pt. Three pages break badly. The sources.yml lead-in on p. 7 and the snapshot lead-in on p. 18 are each separated from their code blocks by about 30% of blank page, and the CI lead-in on p. 23 by about 38%.

## Patterns (things that repeat on many pages — describe once, list pages)
- **Figures scaled down:** all three figures are 5.1–5.7 pt (pp. 11, 14, 17).
- **Lead-in stranded above a big blank because a long code block won't split:** pp. 7, 18, 23 (Medium) and 8 (Low). The code-block style seems to have `break-inside: avoid`. Allow blocks over about 15 lines to split.
- **Tables:** clean; the header is repeated on the Common-mistakes and Option tables when they split (pp. 23→24). No numeric columns.
- **Callouts:** Watch out (pp. 13, 19, 20, 21); styled consistently.
- **Headings with code:** "32.3 Models, sources, and `ref`" and "`ref`: the function…" set the code pill smaller than the heading, which looks like a subscript. Low; not listed separately.
- **Folios** "n / 34"; the footer is correct.
