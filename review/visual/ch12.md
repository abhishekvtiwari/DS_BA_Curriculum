# Visual review — Ch12-Databases-and-SQL-Foundations-v4.pdf (96 pages)
Verdict: v4 adds a much longer §12.13 (pp. 44–67). Its code, tables and callouts are set cleanly, but the new section brings two defects of its own. The Step 11 comparison table has an invisible header cell (white text on a white code pill), the same defect as the WHERE-vs-HAVING table, which is still not fixed. And many PostgreSQL/MySQL statement pairs are printed back to back with no dialect label, in a section whose whole point is the difference between the two. Everything flagged in v3 on the older pages is still present: five figures at 4.9–7.1 pt, the receivables-ageing query wrapping to column 0, clipped exercise numbers (now 10–29), and the pp. 9/11 half-empty pages. Two answer-number strandings from v3 are fixed. Four new ones appear in the longer answers.

Page numbers below are **PDF pages**. The printed folio ("n / 95") is PDF page − 1. The cover has no folio.

## Patterns (things that repeat on many pages — describe once, list pages)
- **Status of the v3 findings on v4 pages.** Still present: invisible WHERE/HAVING header (p. 31), clipped exercise numbers, all five small figures, the ageing-query wrap (p. 71), the pp. 9/11 blanks, mysql-apt-config, Trap 3 pill, split aggregate table, cover label (reworded), contents without numbers, and the appendix note. Fixed: the answer "1." stranding (now p. 86, with its code) and "10." (now p. 89, with its code).
- **§12.13 (pp. 44–67)** is well built overall. Code, output and error blocks all use the same rules; the three tables (statement families, types, FK options) are clean; the Watch out and Dialect note callouts match the rest of the chapter; the cheat sheet repeats its header across pp. 66–67. Its problems are:
  - dialect labelling (V12.11);
  - one invisible header (V12.2);
  - one string-literal wrap (V12.10);
  - inline commands that should be code blocks (V12.12);
  - page-foot lead-ins (6 of the 13 in V12.18).
- **Error output** from PostgreSQL ("ERROR: … DETAIL:") and MySQL ("ERROR 1062 (23000)") uses the same grey output style. That is fine when labelled, but see V12.11.
- **Figure text below the print minimum** in all five figures (pp. 8, 10, 34, 38, 41). Same root cause as elsewhere: the figures are drawn too wide and scaled down.
- **Page-foot strandings:** labels, lead-ins and answer numbers on 18 pages (V12.14, V12.17, V12.18). One keep-with-next rule would fix most of them.
- **Code/output styling** is good. Queries have a dark-blue left rule and output a grey rule. psql output keeps its right-alignment; MySQL output uses +---+ borders.
- **Callouts:** Watch out (peach); Real-life example, Dialect note, Try it, Troubleshooting, Spreadsheet link, Interview extra point and the new "How do you know it worked?" / "The lab rule" boxes (light blue); Simplification note (blue). These are consistent.
- **Folios** are "n / 95" and the running footer is correct throughout.
