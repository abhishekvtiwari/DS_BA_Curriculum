# Visual review — Ch83-The-Long-Game.pdf (17 pages)

Verdict: A short, text-led chapter with clean typography. Its two figures carry the chapter's argument (hours per part, sprinter vs steady), but both are too small to read in print. Figure 83.1 also has a label collision, and Figure 83.2 depends on red-versus-green. The book's closing lines run on unheaded after "Where this leads" onto a mostly empty last page, which reads as overflow rather than a deliberate ending.

Page numbers below are **PDF pages**; the printed folio is PDF page − 1.

- **Images:** none raster.
- **Figure text size:** Fig 83.1 4.8–6.8 pt; Fig 83.2 4.4–6.6 pt.
- **Text outside margins:** none.
- **Blank-area scan:** p. 4 21%, p. 17 72% (last page).
- Every page was viewed, and both figures and all tables were zoomed at 200 dpi.

## Patterns (things that repeat on many pages — describe once, list pages)
- **Figure text below minimum** on both figures (pp. 5, 6). Same template cause as Ch25–27.
- **Colour-only encoding:** Fig 83.2 (red line on green band); also Ch27 Fig 27.2 (red vs green notes). Check all figures in greyscale.

- **Folios** "n / 16", chapter-local. The cover part label is "Closing" and the H1 sub-label is "Closing", consistent with each other.

## Cross-chapter consistency (Ch25, Ch26, Ch27, Ch83)
- **Covers:** same gradient, type and layout in all four. Differences: Ch25 badge "v2", others "v1"; all dated "21 September 2026"; the badge's vertical position shifts with subtitle length (Ch83 highest, Ch25/26 lowest); each has a different footer tagline, which is fine.
- **Contents pages:** identical style in all four, and all lack page numbers. Ch26's contents and H1 use the long title while its cover and footer use the short one; the other chapters match everywhere.
- **Opening page:** H1 "Chapter N. Title" (with a period, while the cover has none), italic part label, Chapter-at-a-glance box. Consistent.
- **Running footer and folio:** identical format ("Analyst to Architect · Chapter N · Title", "n / N"). Numbering restarts every chapter and the contents page is page 1.
- **Headings:** H2 in Poppins 15 pt with a blue rule, preceded by a grey divider; H3 in blue Poppins 12 pt. Consistent. Ch25 ends without the trailing divider that Ch26, 27 and 83 end with.
- **Tables:** the same blue-header style in all four; header rows repeat on page breaks. First-column bold is used inconsistently within and across chapters. Numbers are left-aligned everywhere.
- **Figures:** the same card-and-caption house style, but effective text size ranges from 3.1 pt (Fig 25.2) to 7 pt or more (Fig 26.2). Only Fig 26.2 meets the 7 pt minimum; 25.5 and 27.3 come close. Most figures carry a title, a subtitle and a caption.
- **Callouts:** only "Chapter at a glance" and a generic light-blue box appear. The same box is reused for requirements, use cases, quotes, memos and model answers. None of the named callouts (Watch out, Try it, Simplification note, Real-life example, Interview extra point) appear in any of the four chapters, so their consistency cannot be checked here.
- **Code:** same mono 7.9 pt block style in Ch26, 27 and 83. The left rule is blue for SQL and grey for everything else (Python and terminal included).
- **End matter order:** identical across Ch25–27 (Common mistakes, In the real world, Tools, Project, You've got it when…, Recap, Practice exercises, Key terms, Where this leads, Answers). Ch83 adapts it deliberately.
