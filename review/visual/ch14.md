## Patterns (things that repeat on many pages — describe once, list pages)
- **Wrapped code:** single-line SQL written as one long line, which the layout then wraps to column 0 (V14.8). The Ch13 house style (one clause per line) would remove almost all of it.
- **Split tables handled well:** "Missing values in each tool" (pp. 14–15) and "Common mistakes" (pp. 37–38) repeat the header row on the next page. The cleaning log (V14.11) is the only awkward split.
- **Callouts** (Watch out, Tool note, Simplification note) are styled consistently. The model note to Anita and Vikram (p. 39) reuses the light-blue callout with italic text.
- **Output blocks:** PostgreSQL output has a grey rule and MySQL output is boxed with "+---+". pandas output (pp. 35–37) also uses the grey rule, and so does the pandas **input** (the code blocks on pp. 35–37 have a grey rule, not the blue input rule), so Python input looks like output, as the pilot found in Ch27.
- **Folios** "n / 48"; the running footer is correct.
