# Ch 56 — MLOps: Making Models Survive Production
Verdict: A mature, well-argued chapter. The "input drift is not model decay" experiment (56.8), the business-metric sort in experiment tracking, and the post-mortem story are its strongest teaching. For a first-time reader it has four big problems. (1) The tools are never installed or started: no `pip install` for FastAPI/uvicorn/MLflow, and the server is never actually run. (2) Several core blocks are fragments: the MLflow run has undefined names and a literal `[...]`; `serve.py` has no imports or model loading; the packaging code is never shown. (3) There is a threshold contradiction with Ch 53 (97.5%/0.01 vs the shipped 0.1). (4) Two conclusions clash with the chapter's own numbers: shadow mode is called a "coin flip" by counting verdicts instead of rupees, and the output-layer "early warning" never passes its own 2-point test in Ex 7.
Size: ~1,060 extracted lines, about 25 PDF pages (97–121 of Part VI). Time needed stated: 16–20 hours over three weeks. Plausible? Yes, once a setup section (about 1 hour) and a real server run are added. The load is spread evenly across 11 sections.

## What works (keep)
- 56.8's two-period experiment. PSI screams through the lamp change while recall holds, then stays flat while the new mould drops recall by about 17 points. It is shown by table and figure, and it is a lesson most courses never teach.
- The MLflow sort by `cost_rupees`. It ties back to Ch 53's ₹4,000/₹40 costs and shows that the "best precision" run is not the best run.
- Putting the threshold inside the artifact metadata so rollback restores the decision boundary. The same message is repeated in the runbook and the mistakes table.
- The story, runbook, maturity ladder and "stop at level 2" advice are honest and suit Riverstone's scale.
