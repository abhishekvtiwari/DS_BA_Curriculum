# Ch 19 — Spreadsheet Automation: Macros, VBA, Office Scripts & Google Apps Script
Verdict: Excellent practical judgement: when to use a macro, macro security, recorded-vs-written code, checks, single-owner risk, and a very good "macro that ran for nine years" story. The code, though, was "written and reviewed by hand" and never run. This review found several real bugs:
- a Type-mismatch in `LoopDemo`
- leading zeros that are not kept
- a Summary-sheet delete prompt the comment says won't appear
- `₹` in the VBA editor
- gaps in the size bands
- Office Scripts "freeze panes" that set a row height instead

No VBA, TypeScript or JavaScript block shows its output. The "programming from zero in VBA" claim holds only partly (see 19.1). TypeScript and JavaScript are used for about 150 lines with no teaching at all, and HTML appears here for the first time in the book with no explanation.
Size: ~1,180 lines, ~25 pages (318–342), Time needed stated: 20–25 hours over three weeks; plausible? Yes for a reader who has finished Ch 17–18, because VBA is then a translation. No for a true beginner, or once the recommended TS/JS and HTML primers and shown outputs are added. Then 25–30 hours, with Part 2 of the project (Google Form + triggers) as its own sitting.

## What works (keep)
- 19.1 decision table plus "If Power Query can do it, use Power Query", and the macro-security advice (trusted locations, Mark of the Web, never "enable all").
- 19.2 recorded → rewritten pattern, with the three named faults (selects, literal, depends on what's active). This is exactly the right teaching move.
- 19.6 consolidation design: `Dir` filter, header once, `source_file` column, `ReadOnly:=True`. The 19.9 error handler with `Resume CleanUp`, and 19.10 "read once, work in memory, write once" repeated across all three languages (19.14 table).
- "In the real world" story and 19.15 (single-owner risk, when to stop using macros).
