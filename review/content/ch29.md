# Ch 29 — Python as Software, Not Scripts
Verdict: This is a very good engineering chapter. The "script that works until it doesn't" opening, the 40-line before-script with its problem table, the pure-core/IO-at-the-edges design, the reconciliation test against ₹439,823.50, the retry client and the review checklist are all realistic, and nearly every output I could check is right (pytest percentages, test counts, the jittered waits 0.637 s and 0.619/1.329/2.666 s reproduce exactly with the stated seeds, and the mypy message is real). For a first-time reader it is not yet teachable. Classes, decorators, data classes, type hints, generators, `try/except/else` and TOML are all new, because no earlier chapter teaches them, yet §29.2's first module uses five of them before §29.5–29.8 explain any. pytest is taught for the first time here, but the reader never writes and runs one test alone: the first run shown is a 23-test suite of mostly unseen files. The 60-line API client introduces about 15 new constructs in one block. The prerequisite on Ch 34 must go (D2), and §26.0 covers most, but not all, of the terminal work the chapter does.
Size: ~1,680 extracted lines, 41 pages (pp. 85–125), ~34 code/terminal blocks + 10 answer blocks. Time needed stated: 12–16 hours over two to three weeks. Plausible? No. For a first-time reader this chapter carries a Python course's worth of new language (classes, decorators, typing, generators), two new tools (uv, mypy), a testing framework, a TOML file and a two-part project. With the teaching additions below it is 20–24 hours over three weeks, in four sittings (29.33).

## What works (keep)
- §29.1's method: run the real "before" script for December (right) and January (zero revenue, NaN %, exit code 0, overwrites December's file), then a problem → why it hurts → fixing section table. It motivates every later section with a failure the reader has just watched.
- The design of Figures 29.2/29.3: business rules in pure functions tested on a five-row DataFrame you can add up in your head (₹25,000, 3 orders, 125.0%), plus one integration test that reconciles to a number the book already trusts (₹439,823.50, 115.7%). The failing-test demo (`orders=len(lines)` → `assert 5 == 3`), tied back to Ch 12's fan-out lesson, is excellent.
- The error-handling doctrine: catch named exceptions, never turn failure into a default (`target = 0` → `None`, "no target set"), a `ReportError` base class, one catch at the entry point, exit code 1. The terminal runs for 2025-12 / 2026-01 / Dec-2025 prove it.
- §29.9's mock API with planned failures (503 on page 2, 429 + Retry-After on page 3), the naive client's `KeyError: 'items'`, and the retry/don't-retry figure. "Real World" story and exercise 15 (the review question about discontinuing Furniture) teach judgment, not just code.
