# Ch 52 — The Cloud, Containers & Infrastructure as Code
Verdict: A well-organised survey. It is honest that nothing needing a daemon, cluster or cloud account was executed, and its real checks (CIDR, YAML/HCL parsing, CI trigger simulation) are correct. The secrets-by-layer table and the closing story are excellent. For a first-time reader, though, it packs about eight new technologies into one chapter: cloud service levels, IAM, VPC/CIDR, Docker, Compose, Kubernetes, Terraform and GitHub Actions. It never shows an install, a `docker build`/`run`, `kubectl apply` or `terraform init/plan`. The HCL and Kubernetes YAML are explained resource by resource, not line by line. The configurations as written would also not work together. The Dockerfile would likely fail to build psycopg2 and runs `dagster dev` in production. Two replicas of that would each run the scheduler, so the daily job would run twice. The readiness probe path is likely wrong. The IAM role trusts ECS while the chapter deploys to Kubernetes. The CI pushes without a registry login. And the ~$7/month cost assumes 1 h/day of compute, while the deployment is an always-on server. The IaaS/PaaS/SaaS table moved from Ch 2 is not here yet, and the chapter says the shared-responsibility line "never moves", which is wrong.
Size: ~1,090 lines / 27 pp (181–207). Time needed stated: 12–16 hours over two to three weeks. Plausible? No for a first-time reader. Each of Docker, Kubernetes and Terraform is normally several sittings on its own. Once the installs and run commands (52.6–52.8) are added, 20–26 h is realistic. Better, split the chapter (52.31).

## What works (keep)
- The upfront note "Faking their output would be worse than saying so plainly", with the executed/not-executed line drawn clearly, as in Ch 46/50.
- §52.1's CIDR cell is real arithmetic, and it is right: /16 = 65,536; 256 × /24; 251 usable under AWS's 5 reserved. It ties the subnet plan to the "two AZs" rule, and Figure 52.2 matches the computed subnets.
- The Dockerfile ordering lesson (dependencies before code) is explained through build caching, and it recurs in Figure 52.3, Ex 3 and the recap. So do non-root users and "no secrets in the image".
- §52.6's table (where each secret lives, and where it must not, from laptop to cloud) is a model reference table. The closing Terraform story teaches "read the plan" and "drift between console and code" memorably.
