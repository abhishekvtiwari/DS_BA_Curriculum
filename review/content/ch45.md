# Ch 45 — Data Ingestion & Integration
Verdict: A strong, honest chapter for the reader who reaches it. Every pattern is shown failing on real Riverstone data before it is fixed: the ID-watermark load that misses updates, the guessed CSV types, the renamed column. The reconciliation habit runs through the whole chapter. For a first-time reader, though, it has four problems. (1) It depends on Ch 2 for hashing, and after the approved Ch 2 cut (fix 2.11) Ch 2 no longer holds that material, so the full hashing section must be rebuilt here (placement and content in 45.1). (2) Setup is thin: the install line appears only in the end-of-chapter Tools box, there is no venv, the CDC server change and restart aren't shown for each OS, and psycopg2 and DuckDB are used for the first time with almost no explanation. (3) Several code blocks contradict the chapter's own rules: a reconciliation loop that can't see a status that exists only in the warehouse, a file log that records a file before it is loaded, a raw layer with no file name or load date, a retry function that retries only 429, and a token written into code. (4) Some claims are wrong: "matched by position would put remarks where quantities were expected", DuckDB "handled the day-first dates correctly", "Chapter 2 measured Parquet on large files", and the Ch 47 and Ch 72 cross-references.
Size: 1,319 extracted lines, 33 pages (pp. 4–36 of Part V). Time needed stated: 14–18 hours over two to three weeks. Plausible? Yes as written: about 25 runnable blocks, CDC setup and a 10-step project. With the hashing section moved in from Ch 2, per-OS CDC setup and the extra explanation cells, 15–20 hours is more honest. State four sittings: §45.1–45.4; §45.5–45.6 (hashes, upserts, CDC); §45.7–45.8 (files, schema); §45.9–45.11 plus the project.

## What works (keep)
- §45.4 shows a failure, not just a warning. The load "succeeds", the reconciliation shows it's wrong, and Figure 45.2 draws exactly why ("the load only looks above the line"). The "Watch out: a successful load is not a correct load" box is the thesis of Part V.
- §45.5 "Both methods agree" (hash vs CDC on the same day) is excellent teaching: two independent methods reach the same answer, 10176 changed and 10178 inserted.
- §45.7 carries one five-row file through raw (declared text columns), staging (strptime, replace, TRY_CAST), a rejected-rows list, reconciliation, and a plain-English message to the dispatch supervisor. All numbers reproduce (3,425 units; 374 bytes).
- The strategy table in §45.6, the "Choosing a strategy" table, the build-or-buy table and the web-data checklist in §45.11 are architect-grade and interview-ready.
