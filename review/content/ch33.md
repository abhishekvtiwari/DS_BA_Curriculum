# Ch 33 — The Computer Science You Actually Need
Verdict: One of the strongest chapters in the book: it's practical, the timings are measured, and the core habit ("build an index before the loop, which is a hand-written hash join") is taught memorably and tied back to Ch 28. For a first-time reader, though, it has four real problems. (1) Recursive code appears in §33.4 two sections before recursion is taught in §33.6. (2) The naive matching script, whose timings anchor the whole chapter, is never shown. (3) Several Python ideas are used before they are taught or are never taught at all: generator expressions, `key=`/lambda, decorators, `any`, `frozenset`, heaps. (4) There are wrong numbers and code bugs: the "thirty times the invoices" arithmetic, the Figure 33.2 buckets, an exercise 12 test that checks one value 1,000 times, `band()` on negative amounts, and a "without sorting everything" line that sorts everything. The cycle detector is exponential, which is ironic in a complexity chapter.
Size: ~1,140 extracted lines, 29 pages (pp. 224–252). Time needed stated: 12–16 hours over two to three weeks. Plausible? Yes as written. Once the missing code, the hand trace for DP and the recursion reordering are added, 14–18 hours is more honest. State four sittings: §33.1–33.3; recursion, trees and graphs; searching, sorting and hashing; §33.8–33.10 plus the project.

## What works (keep)
- §33.1's measured table (250 → 2,000 invoices: 0.96 → 7.51 s) with the linear-in-one-input, quadratic-when-both-grow explanation. The extrapolation arithmetic (≈75 s today, ≈5 min when the business doubles) is correct and is exactly the right way to teach Big-O.
- The dictionary index in §33.2. It takes one line and gives a 19,500/500 result, with "When you build a dictionary index in Python, you are hand-writing a hash join". The "Instead of / Do this" table is excellent.
- The real-world story's method: time a slice before guessing, find that the real cost was 20,000 file re-reads, fix the structure, test, and report the 500 unmatched invoices as the business output.
- Exercise answers 6 (boundary values), 7 (iterative BOM with an explicit stack, matching 3.40 kg), 13 (lru_cache hits 175,410 / misses 700) and 17–18 (judgment about n and its future). These are strong and correct.
