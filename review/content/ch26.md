# Ch 26 — The Professional Toolkit: Git, Agile, Documentation & AI Assistants
Verdict: The ideas are taught very well — the three places a file lives, "ask where the change is before asking how to undo it", the six-heading README, "delegate the typing, keep the judgment" — and most commands get a "How it works" list. But as a hands-on tutorial it cannot be followed by a first-timer: it runs 32 terminal command lines (plus mkdir/cd/cp/source/&& implied or in answers) before any terminal teaching (fixed by D2's new §26.0, specified below); it skips the one-time setup every fresh Git needs (identity, default branch `main`, editor, pull behaviour, GitHub authentication), so the reader's very first commit or push fails or prints different output; several commits the text relies on are never made (the WHERE-filter commit, the .gitignore commit that gets amended, the category-split commit on the branch), and §26.3 prints two commits that do not exist until §26.5–26.6. The CI workflow depends on pytest (M.8) and on YAML, which is never introduced.
Size: ~1,070 extracted lines, 21 pages (pp. 444–464), Time needed stated: 6–8 hours; plausible? No — once §26.0 (realistically 45–60 min for a first-timer, not 20), Git install/config, a GitHub account with 2FA and authentication, and the two-hour project are counted, 9–11 hours. The chapter also carries ~55 key terms and three unrelated topics (Git/GitHub/CI, Agile/Jira, AI assistants); it needs explicit sittings.

## What works (keep)
- §26.1's three-places model and Figure 26.1, with the promise that "almost every confusing Git message is Git telling you which of these three it means" — then answer 6 proves it with `MM`. Excellent teaching.
- §26.5's four-undo decision ("Where is the change?") with an explicit, justified refusal to teach `git reset --hard`; the summary table "Is anything lost?".
- §26.4's secrets discipline and the real-world story (a committed `.env` is fixed by changing the password, not by deleting the file) — exactly the right lesson, told memorably.
- §26.9's README test ("hand the URL to a colleague… fifteen minutes"), "files Git cannot diff" (.pbip, exported VBA modules), and §26.11's checking routine and "work on the schema, not the rows".

**§26.0 "The terminal in 20 minutes" — required content (derived from every command Ch 26 uses)**

One sentence: PowerShell works for git commands but not for `source`, `cp`, `set -a` as written in this chapter.
- How to read the book's terminal blocks: `$ ` is the prompt, not typed; `# terminal` is a label/comment; lines without `$` are output; `<file>`, `<hash>`, `<url>`, `<branch>` are placeholders — replace them including the angle brackets; `"…"` means your own message; hashes in the book will differ from yours.
- Anatomy of a command: program, options, arguments — using `git log --oneline -n 2` as the example; short options (`-m`, `-n 2`, `-u`, `-c`, `-q`, `-v`, `-r`, `-a`) vs long (`--oneline`, `--short`, `--staged`, `--stat`, `--amend`, `--no-edit`, `--cached`, `--global`); quoting text with spaces (`-m "Add monthly revenue query"`); commands are case-sensitive.
- Where am I, what's here: `pwd`; `ls`; `ls -a` (hidden dot-files: `.git`, `.gitignore`, `.env`, `.github`); `cd folder`, `cd ..`, `cd ~`; relative vs absolute paths, `.` (as in `git add .`) and `..`; `/` separators, Windows drive as `/c/Users/...` in Git Bash; Tab completion; ↑ for history.
