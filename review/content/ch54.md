# Ch 54 — Generative AI & Large Language Models
Verdict: Excellent framing and business judgment. Next-token prediction via softmax, a BPE tokenizer trained on Riverstone's own emails, temperature measured over 10,000 draws, prompts scored against ground truth, a validate–retry–escalate pipeline, and "the model proposes, the rules dispose". For a first-time reader, though, there are serious problems. (1) The headline "prompting, measured" numbers (12 → 35 → 47) come from a rule-based mock whose behaviour was written to respond to prompt wording, yet the text calls every measurement "real". (2) The one real LLM API call is never installed, configured, run or explained argument by argument. (3) Three code bugs: the BPE trainer mis-merges across symbol boundaries (so "order" comes out as 4 tokens despite a learned `order` token), top-p isn't nucleus sampling as described, and Answers 7 and 14 crash or print impossible numbers. (4) The §54.12 pricing table and Answer 13 are garbled by a `$`-as-math rendering bug.
Size: ~1,320 lines / 30 pages (38–67 of Part VI). Time needed stated: 14–18 hours over three weeks; plausible? Yes for the current text. Adding a real API setup section (account, key, environment variable, first call) and the line-by-line splits proposed below adds 1–2 hours: 15–20 hours.

## What works (keep)
- §54.1 → §54.5 is a clean chain. Logits → softmax (explicitly "Chapter 53's function again") → a measured sampling table. The six-token example recomputes exactly (0.442/0.327/0.147/0.073/0.011/0.000), and the 10,000-draw table reproduces digit for digit with NumPy 2.4.4.
- §54.2 trains a real BPE tokenizer on the chapter's own data and prints the merges as they're learned. It's the best possible way to demystify tokens, billing and spelling failures (once the bug in 54.10 is fixed).
- §54.6–54.7 frame prompting as engineering: one evaluation set, one number per prompt version, a `parse` that treats failures as data, a `validate` that returns reasons, a retry that quotes the problems, and a `needs_a_human` status. "Validation is not accuracy" (59 pass vs 47 right) is a lesson most teams learn the hard way.
- The real-world story (8 demo emails vs 60-email evaluation), the injection Watch-out, and the "prompt first, retrieve for facts, fine-tune for form" table carry senior-level judgment in plain words.
